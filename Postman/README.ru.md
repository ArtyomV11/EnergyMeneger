# Postman для текущего состояния EnergyMeneger

72 запроса, все 7 контроллеров и 22 сочетания метода/маршрута. Коллекция рассчитана на три исходных цеха по 100 кВт, подстанцию 300 кВт, шесть устройств и трёх активных пользователей. Она заменяет старую коллекцию, создававшую четвёртый цех.

## Запуск

1. Импортируйте `EnergyMeneger.postman_collection.json` и `EnergyMeneger.postman_environment.json`. Старую коллекцию и старое environment удалите или переименуйте, чтобы не перепутать их с новыми.
2. Выберите environment **EnergyMeneger localhost 7080 — fixed layout**.
3. Укажите ваши `ownerPassword`, `foremanPassword`, `workerPassword`, которые использовались при успешной инициализации. Все пароли оставлены пустыми. Логины по умолчанию — `owner`, `foreman3`, `worker3`; если в Bootstrap настроены другие логины, исправьте environment.
4. Приложение должно быть запущено. `baseUrl=https://localhost:7080`. Базу заново очищать или инициализировать не нужно.
5. Запустите всю коллекцию сверху вниз: **Functional → Local**, 1 iteration, **Keep variable values** включено. Используйте актуальный Postman с `pm.execution.skipRequest()`.

Токены, сроки действия, ID и снимки настроек сохраняются автоматически. ID не зашиты: цехи ищутся по исходным названиям, оборудование — по имени «Токарный станок». Сохраняйте эти названия для автоматического обнаружения. Первый запрос заново очищает старые токены и ID, проверяет наличие реквизитов всех трёх пользователей и задаёт период отчётов в UTC. При неожиданном HTTP-статусе Runner останавливает дальнейший переход, чтобы ошибка входа не породила десятки ошибочных запросов. Ошибки проверок содержимого также нужно смотреть во вкладке Failed.

## Режимы

- `runWriteTests=false`, `runEquipmentTests=false` — чтение, три входа, роли, чужие цехи, статистика, история, логи и отрицательные проверки входа/параметров. Ничего не создаётся и не переключается.
- `runWriteTests=true` — дополнительно запреты создания/удаления цехов, изменения лимитов, неверных DTO, операций сотрудников без прав владельца. Четыре успешных PUT возвращают ровно текущие значения подстанции, цеха, оборудования и прораба: настройки не меняются, но появляются штатные логи и записи истории. Сотрудники не блокируются, не увольняются, роли не меняются.
- `runEquipmentTests=true` — отдельный дополнительный сценарий включения и выключения существующего токарного станка от имени прораба и владельца. Он запускается только если все шесть устройств выключены. Станок возвращается в выключенное состояние; создаются штатные логи/история. Перед тестом отключите оборудование через Swagger самостоятельно, если оно включено, и не меняйте состояние параллельно из других клиентов.

Ни один режим не добавляет цехи, сотрудников или оборудование и не меняет лимиты. DELETE проверяется для запрещённого удаления цеха и отсутствующего устройства. Успешное физическое удаление оборудования с историей API запрещает. Успешное создание дополнительных пользователей/устройств, увольнение и блокировка исходных сотрудников намеренно не выполняются на вашей чистой базе. Проверка каждого маршрута не означает проверку каждого возможного успешного сценария CRUD.

Если прогон прервался после включения станка в папке 06, выполните **Foreman disables lathe** с сохранённым environment или выключите станок через Swagger. Неожиданное прерывание не позволяет гарантировать восстановление состояния. При обычном завершении папка 07 подтверждает, что осталось три цеха по 100 кВт, три активных роли, шесть устройств и 300 кВт на подстанции.

## Ограничения

API допускает 10 попыток входа в минуту с одного IP. Один прогон выполняет 4 попытки; перед повтором подождите минуту, особенно если входили в Swagger. JWT действует два часа; refresh endpoint отсутствует. Снова выполните папку входов для новых токенов. Если в Postman ошибка локального HTTPS-сертификата — доверьте dev certificate либо отключите SSL certificate verification для локального тестирования.

Отчёты получают UTC-время с `Z`: от суток назад до минуты вперёд. Разрешён период до 31 дня и до трёх лет назад. Для history scope — equipment/workshop; для statistics также factory. Пустая история и нулевая энергия допустимы. Симуляция обновляется раз в 30 секунд, поэтому текущая мощность между запросами может меняться.

Пароли и токены отмечены типом secret. Не публикуйте environment после заполнения реквизитов. В комплекте `Bootstrap.reference.json` с актуальными начальными данными и `DTO-reference.md` со всеми реальными DTO.

## Проверка и пересборка файлов

```powershell
node Postman/build.cjs
node Postman/validate.cjs
```

Генератор создаёт чистое environment с пустыми паролями и токенами. Валидатор проверяет все маршруты контроллеров, переменные, синтаксис и выполнение скриптов на контрольных ответах. Это не заменяет проверку на вашем локальном API.

Дополнительно можно проверить ту же коллекцию из терминала на запущенном приложении:

```powershell
node Postman/run-local.cjs --user-secrets
```

Флаг `--user-secrets` читает реквизиты Bootstrap из локального файла User Secrets и использует их только в памяти. Пароли и токены не выводятся и не сохраняются в environment. Без этого флага реквизиты берутся из переменных процесса `ENERGY_OWNER_PASSWORD`, `ENERGY_FOREMAN_PASSWORD`, `ENERGY_WORKER_PASSWORD` (при необходимости также `ENERGY_OWNER_LOGIN` и соответствующие логины сотрудников). Скрипт допускает только адрес https://localhost:7080.

`--writes` включает дополнительные проверки папки 05. `--equipment` отдельно включает папку 06 с тем же требованием: все шесть устройств изначально выключены. Без флагов запускаются только проверки чтения. Локальная проверка HTTPS в этом вспомогательном скрипте выполняется без проверки dev certificate; публичные адреса запрещены.
