# Чистая база и работа через Swagger

Новая инициализация создаёт подстанцию 300 кВт и ровно три цеха по 100 кВт. Цехи №1 и №2 виртуальные (диапазоны 30–70 и 40–90 кВт), Цех №3 содержит шесть исходных устройств. Все устройства изначально выключены. Создаются владелец, прораб и рабочий; сотрудники закреплены за Цехом №3.

API запрещает создание и удаление цехов, изменение типа моделирования и лимитов 100/300 кВт. Названия, диапазоны виртуальных цехов в пределах 100 кВт и настройки оборудования можно редактировать. Дополнительных сотрудников и оборудование API по-прежнему разрешает создавать при необходимости.

Изменение кода само по себе не очищает существующую базу. Для перехода со старого набора нужен следующий однократный сброс.

## 1. Задайте пароли перед очисткой

Остановите приложение в Visual Studio. В терминале из папки проекта выполните:

```powershell
dotnet user-secrets set "Bootstrap:ForemanLogin" "foreman3"
dotnet user-secrets set "Bootstrap:WorkerLogin" "worker3"
```

Пароли владельца из `Bootstrap:Login` и `Bootstrap:Password` можно оставить прежними. Для новых паролей сотрудников используйте **Manage User Secrets / Управление секретами пользователя** в меню проекта Visual Studio. Добавьте к существующим настройкам (сохранив подключение к БД и JWT):

```json
"Bootstrap:ForemanPassword": "ЗАМЕНИТЕ_СВОИМ_ПАРОЛЕМ",
"Bootstrap:WorkerPassword": "ЗАМЕНИТЕ_СВОИМ_ПАРОЛЕМ"
```

Каждый пароль должен содержать 12–128 символов. Указанный текст — обозначение места для собственного пароля, а не готовые реквизиты. Логины всех трёх пользователей должны различаться без учёта регистра. Новая инициализация проверяет реквизиты до изменений базы и не выводит пароли в консоль.

## 2. Очистите именно базу приложения

Эта операция удаляет все данные восьми таблиц приложения: пользователей, объекты, логи и историю. При необходимости предварительно сохраните резервную копию в pgAdmin. Приложение должно оставаться остановленным.

В Query Tool базы, указанной в `ConnectionStrings:Database` приложения (в предыдущем снимке pgAdmin — `energy_manager`), выполните:

```sql
BEGIN;
TRUNCATE TABLE
    "ActionLogs",
    "EquipmentHistory",
    "WorkshopHistory",
    "Equipment",
    "Users",
    "Workshops",
    "Substations",
    "Factories"
RESTART IDENTITY;
COMMIT;
```

Таблицы и миграции сохраняются; идентификаторы начнутся заново.

## 3. Создайте исходный набор

Из папки проекта:

```powershell
dotnet run --launch-profile EnergyMeneger -- --initialize
```

Профиль устанавливает Development, чтобы использовались User Secrets. Команда создаёт данные и завершается. Если она сообщает, что база уже инициализирована, проверьте выбранную для очистки БД. Не запускайте обычный сервер до успешной инициализации.

Затем запустите приложение через Visual Studio или:

```powershell
dotnet run --launch-profile EnergyMeneger
```

## 4. Вход через Swagger

Откройте https://localhost:7080/swagger и выполните `POST /api/auth/login` через **Try it out → Execute**:

```json
{
  "login": "foreman3",
  "password": "ВАШ_ПАРОЛЬ_ПРОРАБА"
}
```

Для владельца используйте логин из `Bootstrap:Login`; для рабочего — `worker3`. Скопируйте значение `accessToken` из ответа без кавычек, нажмите **Authorize**, вставьте только токен без слова `Bearer`. При смене пользователя выполните **Logout** в Authorize и вставьте новый токен. Токен действует два часа; после сброса базы удалите сохранённую авторизацию и войдите заново.

От имени владельца проверьте:

- `GET /api/substation` — 300 кВт.
- `GET /api/workshops` — три цеха по 100 кВт.
- `GET /api/equipment` — шесть исходных устройств.
- `GET /api/users` — три активных пользователя с ролями Owner, Foreman и Worker.

Прораб и рабочий видят только свой Цех №3. Прораб может включать и выключать оборудование; рабочий — только просматривать. При превышении мощности включение может вернуть ожидаемый 409. Создание четвёртого цеха, удаление существующего и смена лимитов всегда возвращают 409 для владельца. Для пользователей без прав владельца эти операции возвращают 403.

История и логи начинают накапливаться после запуска симуляции — это нормальная работа. Старую коллекцию Postman не запускайте: она рассчитана на создание дополнительного цеха и увеличение лимита.
